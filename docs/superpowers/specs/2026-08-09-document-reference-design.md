# 文档参考输入设计

## 目标

在现有文章创作输入页增加 PDF、Word、TXT、Markdown 文件参考能力。用户上传文件后，后端在内存中提取文本并调用现有 DashScope 模型生成摘要；摘要与用户输入的选题一起参与当前文章创作流程。原始文件只存在于本次 HTTP 请求内，不保存到磁盘、对象存储或数据库。

## 方案

采用“解析接口 + 创建任务摘要字段”的方案：

1. 前端调用 `POST /api/article/reference/parse` 上传单个文件。
2. Java 后端校验扩展名和 10 MB 大小，在内存中用 PDFBox/Apache POI 提取文本，限制送入摘要模型的文本长度。
3. 后端使用现有 DashScope ChatModel 总结为可供创作使用的参考摘要，返回文件名、摘要和字符数。
4. 前端展示已解析文件和摘要状态，创建任务时把摘要放入 `referenceSummary`。
5. 文章任务保存摘要字段；标题、大纲、正文阶段分别读取该字段，作为“参考材料”附加到原有 prompt。没有文件时保持原有行为。

## 文件范围与限制

- 支持：`.pdf`、`.doc`、`.docx`、`.txt`、`.md`。
- 单文件最大 10 MB；单次只保留一个参考文件，重新上传会替换旧摘要。
- 提取不到有效文字、扩展名不支持或摘要失败时返回明确错误，不能创建半成品任务。
- 只保存摘要，不保存原文件；摘要长度限制为 4,000 个字符，避免后续 prompt 无限增长。
- 文档内容作为不可信参考材料处理，摘要 prompt 明确要求忽略文档中的指令性内容。

## 验证

- Java 单元测试覆盖扩展名、大小校验、TXT 提取与空文本拒绝。
- Maven 测试与打包验证后，前端执行 `npm run build` 和 `git diff --check`。
- 用已打开的 Chrome 访问 `http://localhost:5173/`，进入创作页检查上传控件、摘要状态、移动端布局和失败提示；不触发真实文章生成以避免消耗配额。
