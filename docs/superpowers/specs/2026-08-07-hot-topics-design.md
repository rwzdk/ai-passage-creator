# 实时热门选题设计规格

## 1. 目标

将创作页右侧固定的热门选题替换为可实时刷新的网络热门内容，同时保留本地备用选题，确保外部服务不可用时创作页仍然可用。

本次只覆盖热门选题查询和展示，不改变文章生成、标题选择、大纲确认、正文流式生成和配图流程。

## 2. 方案

采用后端代理 GNews API 的方式：

- 后端保存 `GNEWS_API_KEY`，前端不接触密钥。
- 后端提供 `GET /api/article/hot-topics`，统一返回项目自己的数据结构。
- 后端缓存成功结果 10 分钟，避免每次打开创作页都请求外部服务。
- 外部服务失败、密钥缺失或返回空数据时，接口返回本地备用选题并标记数据来源为 `fallback`。
- 前端首次进入创作页自动请求，提供手动刷新按钮；刷新中保留旧数据，不阻塞正文输入。

## 3. 数据结构

```json
{
  "code": 0,
  "data": {
    "source": "gnews",
    "updatedAt": "2026-08-07T12:00:00+08:00",
    "items": [
      {
        "title": "热门新闻标题",
        "source": "新闻来源",
        "publishedAt": "2026-08-07T11:50:00+08:00",
        "url": "https://news.google.com/"
      }
    ]
  }
}
```

前端只使用 `title` 填充创作选题；来源和更新时间用于辅助展示，链接使用新窗口打开，不能覆盖当前创作状态。

## 4. 后端边界

新增独立的热门选题服务和控制器接口：

- 配置项：`gnews.api-key`、`gnews.base-url`、`gnews.cache-minutes`、`gnews.max-items`。
- 默认使用中文、国内新闻和综合分类参数。
- 只保留标题、来源、发布时间和链接，不把外部完整正文写入数据库。
- 使用超时、状态码校验、响应格式校验和异常日志；日志不输出 API Key。
- 本地备用选题作为常量集中维护，避免散落在控制器中。

## 5. 前端交互

创作页热门选题区域包含：

- 标题、来源标识和最后更新时间。
- 每个选题使用可点击标签，点击后填入主题输入框并保持页面滚动位置。
- “刷新热门”按钮带加载状态，失败时显示轻量提示但不清空已有内容。
- 初次加载显示骨架动画；无数据时显示备用选题。
- 支持 `prefers-reduced-motion`，减少刷新旋转和标签入场动画。

## 6. 失败与安全

- 未配置 API Key：直接返回备用选题，接口仍返回成功响应，避免前端报错。
- 外部请求超时或限流：返回最近一次缓存；没有缓存时返回备用选题。
- 外部标题为空或异常：过滤后再返回，禁止把空标题渲染为可点击内容。
- 外部链接仅作为新窗口访问目标，不影响主题输入和文章任务。
- API Key 只配置在后端本地配置文件或环境变量，不提交到 Git。

## 7. 验收标准

- 创作页不再依赖固定数组作为唯一数据来源。
- 有效 API Key 时能够展示网络热门标题、来源和更新时间。
- 无 Key、网络错误、超时和空响应时仍能展示备用选题。
- 点击热榜标题能够填充选题输入框，之后可正常开始创作。
- 刷新过程中输入框和开始创作按钮保持可用。
- 前端类型检查、构建和差异检查通过；后端新增服务有针对成功、失败和备用数据的测试。
