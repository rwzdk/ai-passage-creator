# 创作帮助与反馈设计

## 目标

为文章创作页已有的“使用帮助”和“反馈建议”入口补齐可用功能。帮助内容在页内弹窗呈现；反馈允许已登录用户填写建议并附加图片，服务端将邮件发送到 `235173498@qq.com`。

## 交互与视觉

沿用创作页现有的 Ant Design Vue 控件、绿色主题变量、圆角和间距，不新增路由。

- “使用帮助”打开可关闭的中等宽度弹窗，以 5 个步骤说明选题输入、风格与配图、生成标题、确认大纲、查看与导出成品。
- “反馈建议”打开表单弹窗：反馈内容为必填项，限制 1,000 个字符；图片为可选项，支持 JPG、JPEG、PNG、WEBP，最多 3 张、每张最大 5 MB。弹窗提交中禁止重复提交，成功后清空表单并关闭，失败时保留内容和图片以便重试。
- 上传组件显示缩略图、单项移除和超限提示，键盘可关闭弹窗，移动端宽度随视口收缩。

## 服务端与数据流

新增 `POST /api/feedback`，要求已登录，使用 `multipart/form-data` 接收 `content` 和可选的 `images`。控制器只负责请求绑定与身份获取；服务层负责校验、组装邮件和调用邮件发送器。上传图片仅保留在请求内存中并作为邮件附件发送，不落盘、不入库。

邮件固定收件人为 `235173498@qq.com`，主题包含“创作平台反馈建议”。正文包含用户昵称、账号、用户 ID、提交时间和反馈内容；附件保留安全化后的原始文件名。配置以 `feedback.mail.*` 表达收件地址和发件人展示名，SMTP 主机、端口、用户名、密码使用 Spring Mail 标准配置；其中用户名和授权码分别由 `MAIL_USERNAME` 与 `MAIL_PASSWORD` 环境变量提供，不写入仓库。

## 错误处理与边界

- 未登录沿用项目现有未登录响应。
- 空白反馈、过长内容、过多文件、格式不支持和文件超限均在服务端拒绝；前端同步做体验校验。
- SMTP 未配置或邮件发送失败返回不泄露凭据的“反馈发送失败，请稍后重试”。
- 图片文件名不参与文件系统路径，仅作为附件显示名使用。

## 验证

- Java 测试覆盖空反馈、非法图片、图片数量和大小边界，以及正确参数被组装为邮件正文和附件。
- 前端构建验证与创作页手动检查覆盖两个入口、表单校验、上传移除和提交状态。
